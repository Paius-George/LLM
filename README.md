# 1. What is an LLM?

A **Large Language Model (LLM)** is a **Transformer**-type neural network trained on massive amounts of text to understand and generate natural language and code. At each inference step, the model receives a sequence of **tokens** and computes the probability for the next token through the **Attention** mechanism.

The model used in this guide is **Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill**, a 14B-parameter Qwen3 model fine-tuned (distilled) on a dataset generated by Claude Opus 4.5 with high reasoning effort. It is specialized in **coding, science, and complex reasoning**, combining the efficient Qwen3 architecture with the thinking style of Claude Opus.

### 1.1. Quantization: how to fit 14B parameters into 8GB VRAM

A 14B-parameter model takes up ~28 GB in FP32. Through **quantization**, the numerical precision of each parameter is reduced, drastically shrinking the size with minimal loss of quality.

| Format     | Size       | Required VRAM | Quality            |
| ---------- | ---------- | ------------- | ------------------ |
| BF16/F16   | 29.5 GB    | 30+ GB        | Reference          |
| Q8_0       | 15.7 GB    | 16+ GB        | Excellent          |
| Q4_K_M     | 9.0 GB     | ~9.5 GB       | Very good          |
| **IQ4_NL** | **8.6 GB** | **~8.8 GB**   | **Recommended 8GB** |
| Q3_K_M     | 7.32 GB    | ~7.5 GB       | Good, VRAM margin  |
| Q3_K_S     | 6.66 GB    | ~7 GB         | Acceptable         |

> **IQ4_NL** is the recommended format for 8 GB VRAM GPUs. It offers quality close to Q4_K_M at a smaller size. If you have exactly 8 GB, as I do, and you run other processes at the same time, choose **Q3_K_M**.

### 1.2. Why llama.cpp?

`llama.cpp` is the inference engine written in C/C++ that underpins most local LLM tools. Advantages over the alternatives:

- **Optimal CUDA support** — uses cuBLAS for maximum acceleration on NVIDIA
- **GGUF format** — the universal format for quantized models
- **HTTP server** — very easy to use for running the LLM locally
- **Control** — full control over the configuration

## 2. Hardware Specifications

| Component | Recommended Minimum | Role                                |
| --------- | ------------------- | ----------------------------------- |
| GPU       | NVIDIA 8GB+ VRAM    | CUDA-accelerated inference (cuBLAS) |
| CPU       | 8+ modern cores     | Compiling llama.cpp, CPU offloading |
| RAM       | 16 GB DDR4+         | OS + layers offloaded from VRAM     |
| Driver    | NVIDIA 525+         | Required for CUDA 12.x              |

### VRAM Calculation

```
Model: Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill — format IQ4_NL

GGUF file size        : 8.6 GB
+ KV cache (ctx 8192) : ~0.4 GB
+ CUDA overhead       : ~0.3 GB
= Estimated total     : ~9.3 GB

→ On an 8 GB GPU: I'll use --n-gpu-layers 35 (offload ~2 layers to RAM)
→ On a 10+ GB GPU: --n-gpu-layers 999 (everything on the GPU)
```

Alternatively, with **Q3_K_M (7.32 GB)** everything fits on an 8 GB GPU without offloading.

## 3. Installing llama.cpp

### 3.1. System dependencies

Check that CUDA is available:

```bash
nvcc --version     # should display CUDA 12.x
nvidia-smi         # should display the GPU and the driver
```

### 3.2. Cloning and compiling with CUDA support

```bash
# Clone the repository
git clone https://github.com/ggerganov/llama.cpp
cd llama.cpp

# Compile with CUDA (cuBLAS) — takes ~2-5 minutes
cmake -B build \
  -DGGML_CUDA=ON \
  -DCMAKE_CUDA_ARCHITECTURES=86   # Ampere (RTX 30xx)
  # For RTX 40xx use: -DCMAKE_CUDA_ARCHITECTURES=89
  # For RTX 20xx use: -DCMAKE_CUDA_ARCHITECTURES=75

cmake --build build --config Release -j$(nproc)
```

> **CUDA architectures by generation:**
>
> - RTX 20xx (Turing) → `75`
> - RTX 30xx (Ampere) → `86`
> - RTX 40xx (Ada) → `89`
> - RTX 50xx (Blackwell) → `120`

## 4. Downloading the GGUF Model

The model is available on [HuggingFace](https://huggingface.co/TeichAI/Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill-GGUF).

### 4.1. Choose the right format for your VRAM

| Format     | Size       | When to choose                            |
| ---------- | ---------- | ----------------------------------------- |
| Q3_K_M     | 7.32 GB    | GPU exactly 8 GB, you want a safety margin |
| **IQ4_NL** | **8.6 GB** | **GPU 8 GB+**                             |
| Q4_K_M     | 9.0 GB     | GPU 10+ GB                                |
| Q8_0       | 15.7 GB    | GPU 16+ GB, maximum quality               |

### 4.2. Downloading with llama.cpp

```bash
pip install huggingface-hub --break-system-packages

# Create the directory for the model
mkdir -p ~/models/

# Download IQ4_NL (~8.6 GB) — recommended for 8GB VRAM
LLAMA_CACHE=~/models llama-server \
           -hf TeichAI/Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill-GGUF:IQ4_NL \
           --host 0.0.0.0 \
             --port 8080 \
             --n-gpu-layers 999 \
             --ctx-size 8192 \
             --threads 8 \
             --parallel 2
```

## 5. Starting the llama.cpp Server

`llama-server` exposes an OpenAI-compatible HTTP API on port `8080`. Open WebUI connects directly to this endpoint.

### 5.1. Basic command

```bash
llama-server \
  --model ~/models/qwen3-14b-reasoning/Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill-IQ4_NL.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  --n-gpu-layers 999 \
  --ctx-size 8192 \
  --threads 8 \
  --parallel 2
```

<img alt="image" src="https://github.com/user-attachments/assets/73204b84-5150-4768-8239-4e9421a8bfa7" />


### 5.2. Explanation of the parameters

| Parameter            | Value          | Effect                                                   |
| -------------------- | -------------- | -------------------------------------------------------- |
| `--n-gpu-layers 999` | max layers     | Sends all layers to the GPU (if VRAM allows)             |
| `--n-gpu-layers 33`  | partial layers | Partial offload — for GPUs with exactly 8 GB             |
| `--ctx-size 8192`    | token context  | How much context it can process at once (larger = slower) |
| `--threads 8`        | CPU threads    | Threads for layers on the CPU and pre-processing         |
| `--parallel 2`       | sessions       | How many simultaneous requests the server can handle     |
| `--batch-size 512`   | batch tokens   | Tokens processed in parallel — increases throughput      |

### 5.3. Command optimized for 8 GB VRAM

```bash
# With IQ4_NL — may require offloading ~2 layers to RAM
llama-server \
  --model ~/models/qwen3-14b-reasoning/Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill-IQ4_NL.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  --n-gpu-layers 35 \     # adjust: 999 if VRAM allows, 30-35 if OOM
  --ctx-size 8192 \
  --threads $(nproc) \
  --batch-size 512 \
  --parallel 1 \
  --log-disable

# With Q3_K_M — everything on the GPU without offloading
llama-server \
  --model ~/models/qwen3-14b-reasoning/Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill-Q3_K_M.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  --n-gpu-layers 999 \
  --ctx-size 8192 \
  --threads $(nproc) \
  --batch-size 512 \
  --parallel 1 
```

### 5.5. Running as a systemd service

To start the server automatically at boot:

```bash
sudo nano /etc/systemd/system/llama-server.service
```

```ini
[Unit]
Description=llama.cpp Server
After=network.target

[Service]
Type=simple
User=YOUR_USERNAME
ExecStart=/usr/local/bin/llama-server \
  --model /home/YOUR_USERNAME/models/qwen3-14b-reasoning/Qwen3-14B-Claude-4.5-Opus-High-Reasoning-Distill-IQ4_NL.gguf \
  --host 0.0.0.0 \
  --port 8080 \
  --n-gpu-layers 35 \
  --ctx-size 8192 \
  --parallel 1
Restart=always
RestartSec=5
Environment=CUDA_VISIBLE_DEVICES=0

[Install]
WantedBy=multi-user.target
```

```bash
# Enable the service
sudo systemctl daemon-reload
sudo systemctl enable llama-server
sudo systemctl start llama-server

# Verify
sudo systemctl status llama-server
journalctl -u llama-server -f    # live logs
```

## 6. Optimization for coding

### 6.1. Recommended System Prompt

This model is distilled on the reasoning of Claude Opus 4.5 — it works best with clear instructions and requests for step-by-step explanations.

In WebUI → Settings → General → System Message:

```
You are an expert software engineer with strong reasoning capabilities.
When solving problems:
- Think step by step before writing code
- Explain your reasoning, then provide the implementation
- Point out edge cases, potential bugs, and security issues
- Suggest improvements and alternatives where relevant
- Write clean, well-commented, production-ready code

Default to Python unless specified. For shell scripts, target Linux/bash.
Respond in the same language as the user (RO/EN).
```

### 6.2. Generation parameters for code

|Parameter|Value|Rationale|
|---|---|---|
|Temperature|0.1 – 0.3|Deterministic code, correct syntax|
|Top-P|0.9|Controlled diversity|
|Repeat Penalty|1.1|Avoids pointless code repetition|
|Max Tokens|2048|Complete responses without truncation|

> Temperature > 0.7 increases creativity but introduces syntax and logic errors in code. Keep it below 0.3 for programming.

## 7. Troubleshooting

### The model runs on the CPU (slow, <5 tok/s)

```bash
# Check GPU layers in the server's startup output
# It should show: "llm_load_tensors: offloaded XX/XX layers to GPU"

# If 0 layers are on the GPU → problem with the CUDA build
./build/bin/llama-server --version
# Check that the output shows: "BLAS = 1, GPU = CUDA"

# Recompile making sure nvcc is in PATH
which nvcc && nvcc --version
cmake -B build -DGGML_CUDA=ON && cmake --build build -j$(nproc)
```

### Out of Memory (CUDA OOM)

```bash
# Reduce the number of layers on the GPU
# Try decreasing values: 35 → 30 → 25
llama-server \
  --model ~/models/.../model.gguf \
  --n-gpu-layers 30 \     # ← reduce until the error disappears
  ...

# Or use a smaller context
--ctx-size 4096   # instead of 8192
```

### Low inference speed

| Symptom       | Probable cause       | Solution                  |
| ------------- | -------------------- | ------------------------- |
| < 5 tok/s     | Running on the CPU   | Recompile with CUDA       |
| 5 – 15 tok/s  | Partial offload      | Increase `--n-gpu-layers` |
| 15 – 40 tok/s | Normal for 14B Q4    | Acceptable performance ✓  |
| > 40 tok/s    | Optimal configuration | Excellent ✓               |

## 9. Cheat Sheet

```bash
# ── BUILD ─────────────────────────────────────────────────────
git clone https://github.com/ggerganov/llama.cpp && cd llama.cpp
cmake -B build -DGGML_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES=86
cmake --build build -j$(nproc)

# ── MODEL INSTALLATION ─────────────────────────────────────────────────────
LLAMA_CACHE=~/models llama-server \
           -hf model/model:quantization \
           --host 0.0.0.0 \
             --port 8080 \
             --n-gpu-layers 999 \
             --ctx-size 8192 \
             --threads 8 \
             --parallel 2

# ── SERVER ────────────────────────────────────────────────────
llama-server \
  -m ~/models/model.gguf \
  --host 0.0.0.0 --port 8080 \
  --n-gpu-layers 35 --ctx-size 8192

# ── STATUS ────────────────────────────────────────────────────
curl http://localhost:8080/health         # check server
curl http://localhost:8080/v1/models      # list models
nvidia-smi                                # GPU usage
journalctl -u llama-server -f             # live logs

# ── ACCESS ─────────────────────────────────────────────────────
# llama.cpp   →  http://localhost:8080
```
